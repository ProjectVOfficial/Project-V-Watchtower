PROJECT V WATCHTOWER — PHASE 19.4
APPLICATION BRIDGE FOUNDATION

Target project:
E:\PROJECTS\worldmonitor-2.5.23

INSTALL
1. Close Watchtower.
2. Extract this ZIP.
3. Copy the included src folder into:
   E:\PROJECTS\worldmonitor-2.5.23
4. Choose Replace files in destination.
5. From PowerShell in the project folder run:
   npm run typecheck
6. If typecheck is clean, launch with:
   npm run desktop:dev

WHAT THIS PHASE ADDS
- V menu section 05: PROJECT V BRIDGE
- Bridge cards for Project V Browser, Project V Chat, and Shadow Gallery
- Native executable selection through the existing approved Launch Deck picker
- Persistent local binding between each Project V app and its Launch Deck record
- OPEN / CONNECT / RECONNECT / DISCONNECT controls
- READY / DETECTED / NEEDS APPROVAL / NOT CONNECTED status
- Ctrl+K ECOSYSTEM commands for the three Project V applications
- Ctrl+K command to jump directly to Project V Bridge configuration
- Existing Launch Deck approval and safe-process-launch path remains in control
- URL/file handoff capability flags are prepared for later phases but deep IPC is not enabled yet

FIRST TEST
1. Open V and scroll to 05 PROJECT V BRIDGE.
2. Confirm all three cards appear.
3. Click CONNECT on Project V Browser and select its executable.
4. Confirm the card becomes CONNECTED · READY and the counter becomes 1 / 3 READY.
5. Click OPEN and confirm the configured application launches.
6. Close it, press Ctrl+K, type "project v browser", and run OPEN PROJECT V BROWSER.
7. Restart Watchtower and confirm the browser binding remains READY.
8. DISCONNECT should remove only the Watchtower bridge binding; it does not uninstall or delete the external application.

FOUNDATION SCOPE
This phase intentionally does not merge the Browser, Chat, or Shadow Gallery codebases into Watchtower. It establishes the stable local application registry and launch/handoff boundary that later integration can build on.
