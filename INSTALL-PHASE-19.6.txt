PROJECT V WATCHTOWER — PHASE 19.6
WATCHTOWER STARTUP ACCESS GATE

Target project:
E:\PROJECTS\worldmonitor-2.5.23

INSTALL
1. Close Watchtower.
2. Extract this ZIP.
3. Copy the included src folder into:
   E:\PROJECTS\worldmonitor-2.5.23
4. Choose Replace files in destination.
5. From PowerShell in the project folder run:
   npm run typecheck
6. If typecheck is clean, launch with:
   npm run desktop:dev

WHAT THIS PHASE ADDS
- Optional PIN-based Watchtower Access Gate at startup.
- The command deck is visually blocked before the primary Watchtower interface is revealed when the gate is armed.
- Reuses the existing Project Lock PBKDF2-SHA256 PIN verifier; the plaintext PIN is not stored.
- New V drawer section 07: ACCESS GATE.
- Drawer status: NOT ARMED / PIN READY / ARMED.
- LOCK NOW action from the V drawer.
- Ctrl+K command: LOCK WATCHTOWER.
- Project Lock / auto-lock can return to the Watchtower access screen when the startup gate is armed.
- Removing the Project Lock PIN automatically disables the startup gate.
- Access-gate visuals follow Watchtower Classic, Project V Shadow, and Midnight theme tokens.
- Existing workspace, Mission Profile, Quick Bar, Project V Bridge, alert, case, and layout persistence are left intact.

SECURITY BOUNDARY
The startup Access Gate is local application access control. It is intended to prevent casual unauthorized entry to an already signed-in Windows session. It does not encrypt Watchtower's stored cases, layouts, caches, or backups and does not replace Windows sign-in, BitLocker/full-disk encryption, or endpoint security.

FIRST TEST
1. Launch Watchtower.
2. Open SECURITY -> PROJECT LOCK.
3. If no PIN exists, enter the same 4-12 digit test PIN in both PIN fields and choose SET PIN.
4. Enable REQUIRE PIN WHEN WATCHTOWER STARTS.
5. Open V and confirm 07 ACCESS GATE reports ARMED.
6. Close Watchtower completely and launch it again.
7. The Watchtower command deck should not be revealed. The WATCHTOWER ACCESS GATE screen should appear and request the PIN.
8. Enter one incorrect PIN and confirm ACCESS DENIED appears.
9. Enter the correct PIN and confirm the previous Watchtower workspace / Mission Profile returns normally.
10. Press Ctrl+K, type "lock watchtower", run it, and confirm the access screen returns.
11. Unlock again, open V, use LOCK NOW, and confirm the same behavior.
12. In SECURITY -> PROJECT LOCK, disable REQUIRE PIN WHEN WATCHTOWER STARTS. Restart Watchtower and confirm it opens directly without the startup gate.
13. Re-arm it if desired for normal use.

FAILED ATTEMPTS
The existing Project Lock retry behavior remains active: after five failed attempts, PIN entry is temporarily disabled for 15 seconds before another attempt can be made.

PHASE SCOPE
Phase 19.6 intentionally uses Watchtower's existing local PIN verifier rather than introducing shared authentication with Project V Browser, Project V Chat, or Shadow Gallery. Cross-application authentication remains separate. Windows Hello / platform biometric integration can be considered later after the local access-gate flow is stable.
